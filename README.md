# Welvar Taste Craft: Модульная дизайн-система и Research Pipeline

Библиотека модульных дизайн-навыков, инженерных правил доступности и исследовательский pipeline для анализа визуальных материалов.
Система направлена на устранение шаблонных генераций как первого порядка (неоновые пятна, водянистый маркетинг, 3 одинаковые карточки), так и второго порядка (догматическое навязывание темного tech-стиля, обязательного bento 7:5, запрета таблиц или искусственных наложений).

Проектирование строится от задачи пользователя, структуры данных, контекста бренда и обязательных требований доступности (WCAG 2.1 AA, навигация с клавиатуры, touch-эргономика, reduced-motion).

## 2. Подключение и использование

Для использования в ИИ-ассистентах (Claude Code, Antigravity, Cursor, Codex):
- **Основная точка входа:** сошлитесь на `skills/masterpiece-taste-design/SKILL.md` (или корневой `SKILL.md`).
- **Точечная активация поднавыков:** при решении конкретной задачи подключайте только необходимый поднавык (например, `skills/masterpiece-taste-design/sub-skills/figma-mastery` для работы с компонентами Figma или `skills/masterpiece-taste-design/sub-skills/web-and-native-ui` для верстки).
- Не загружайте все справочники по умолчанию — они служат контекстными руководствами при необходимости.

### Пример рабочего промпта

```text
Спроектируй экран расписания мастер-классов в веб-интерфейсе:
1. Используй навыки из skills/masterpiece-taste-design/SKILL.md и skills/masterpiece-taste-design/sub-skills/reference-and-components/SKILL.md.
2. Формат: плотная таблица таймлайна с колонками времени, аудитории, спикера и статуса свободных мест.
3. Доступность: соблюдение контраста текста по WCAG 2.1 AA, поддержка .focus-ring:focus-visible при навигации с Tab, учет prefers-reduced-motion.
4. Ограничения: светлая рабочая тема, без искусственных неоновых градиентов, без декоративных метрик-заглушек и без навязанного темного стиля.
```

## 3. Пример процесса работы

1. **Формирование брифа:**
   Зафиксировать субъект, задачу, реальную структуру данных и ограничения проекта (WCAG 2.1 AA, платформу, требования бренда).
2. **Композиционные гипотезы (для новых концепций):**
   Для одной и той же задачи сформулировать 2–3 принципиально разные гипотезы (например, инструментальная, витринная, редакционная — выбор жанров зависит от задачи и приводится для примера) и составить Section Purpose Map без фиксированного числа секций.
3. **Реализация интерфейса:**
   - Для реестров, расписаний и логов — использовать плотные функциональные таблицы.
   - Для равнозначных категорий — сетки из 2–3 колонок.
   - Для доминирующего объекта — асимметричный сплит или бенто-сетку.
   - Обеспечить все состояния элементов (default, hover, active, focus-visible, disabled, loading, empty, error).
4. **Контрольный аудит (Pre-Flight):**
   Проверить макет по наблюдаемым критериям чеклиста [`skills/masterpiece-taste-design/references/anti_slop_checklist.md`](skills/masterpiece-taste-design/references/anti_slop_checklist.md).

## 4. Команды для проверок

Все проверки могут выполняться в офлайн-режиме стандартными средствами окружения:

```bash
# Установка базовых зависимостей окружения (tinycss2 опционален для проверки токенов)
pip install -r requirements.txt
# Опционально: pip install tinycss2

# Проверка валидности локальных Markdown-ссылок и frontmatter в SKILL.md
python scripts/validate_markdown_and_frontmatter.py

# Запуск тестов валидатора и анализатора
python -m unittest discover -s tests -p "test_*.py"

# Проверка синтаксиса tokens.css (требует опциональный tinycss2)
python scripts/check_tokens.py

# Запуск скрейпера в автономном демо-режиме во временную папку (не затрагивая tracked data)
python scraper/pipeline.py --mode demo --data-dir tmp_demo_data

# Запуск модульного теста парсера экспорта Telegram
python scraper/test_export.py

# Проверка статуса рабочей копии git
rtk git status
```
