# Web Engineering & Accessibility Standards

Инженерные стандарты верстки веб-интерфейсов на React / Next.js / Tailwind v4.

---

## 1. Сетка и компоновка

- **CSS Grid для многомерных структур:** таблицы расписаний, карточные каталоги и дашборды верстаются на CSS Grid с адаптивными брейкпоинтами:
  `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6`.
- **Flexbox для однонаправленных потоков:** панели инструментов, строки действий, меню.
- **Стабильность высоты Viewport:**
  - Единица `dvh` динамически пересчитывается при сворачивании и разворачивании интерфейса мобильного браузера, что может вызывать перерисовку или микро-сдвиги контента.
  - Для фиксированных первых экранов надежнее использовать `svh` или протестированные контейнеры. Не требовать полноэкранную высоту для всех экранов подряд; применять только там, где этого требует сценарий.

---

## 2. Доступность (Accessibility)

- **Контрастность:** соответствие WCAG 2.1 AA (не менее 4.5:1 для основного текста, 3:1 для крупного текста).
- **Клавиатурный фокус:**
  ```css
  :focus-visible {
    outline: 2px solid var(--border-interactive, #2563eb);
    outline-offset: 2px;
  }
  ```
- **Снижение движения (`prefers-reduced-motion`):**
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration: 0.01ms !important;
    }
  }
  ```
- **Семантика HTML:** использование `<header>`, `<nav>`, `<main>`, `<section>`, `<table>`, `<button>` вместо нагромождения бессмысленных `<div>`.
- **Touch-мишени на мобильных:** 44x44px — проектный ориентир для отдельных кнопок и управляющих элементов, но не безусловное требование WCAG для встроенных inline-ссылок в тексте.

## 3. Интерактивные состояния и модальные окна

- **Кнопки:** однострочный емкий текст (1-3 слова), визуальный отклик на нажатие (`active:scale-[0.98]` или `transform: translateY(1px)`).
- **Поля ввода:** видимая метка (`<label>`) над полем, индикация ошибки и вспомогательный текст.
- **Стандарт доступных модальных окон (WAI-ARIA Focus Trap):**
  Любые модальные окна обязаны:
  1. Блокировать скролл страницы (`document.body.style.overflow = 'hidden'`).
  2. Захватывать и удерживать фокус клавиатуры внутри окна (циклическая навигация по `Tab` / `Shift+Tab`).
  3. Закрываться по нажатию клавиши `Escape` и клику на подложку (`backdrop`).
  4. Автоматически возвращать фокус на элемент, вызвавший открытие, при размонтировании.
  5. Иметь атрибуты `role="dialog"`, `aria-modal="true"`, `aria-label={title}`.
  (Полный эталонный компонент: см. [archive_1_masterpiece_exemplar.md](archive_1_masterpiece_exemplar.md)).

## 4. Мобильная эргономика и touch-мишени 44x44px

На экранах смартфонов и планшетов (`@media (max-width: 760px)`):
- Для компактных кнопок (например, смена направления `swap-btn`, стрелки слайдера, закрытие) используется размер 44x44px либо псевдоэлемент расширения зоны касания:
  ```css
  .swap-btn:before {
    content: '';
    position: absolute;
    width: 44px;
    height: 44px;
    left: 50%;
    top: 50%;
    transform: translate(-50%, -50%);
  }
  ```
- Кнопки-счетчики пассажиров, фильтры и ссылки навигации должны иметь `min-height: 44px`.

## 5. Запрет мета-комментирования и карго-культа в коде

- **Запрещено** писать комментарии в коде с названиями концепций из скилла: `{/* Anti-Slop Grid */}`, `/* Kinetic discipline */`, `/* Liquid glass */`.
- Код должен быть чистым, лаконичным, без саморекламы и мета-рассуждений модели.
- Эталон чистоты архитектуры: [archive_1_masterpiece_exemplar.md](archive_1_masterpiece_exemplar.md).
